Getting started

Matchstick (MGDF) runs your game. It opens the window, creates the Direct3D 12 device, and drives the game loop. You write a DLL that draws and updates.

You will learn

  • How Matchstick and your game fit together
  • How to lay out a game folder
  • How to write a minimal game module
  • How to run and debug it

How it works

Your game is a DLL called a module. The host, core.exe, loads it and calls it once per simulation tick and once per frame. In return, the module calls the host for audio, input, files, networking and settings.

Rendering is the exception. Matchstick doesn't wrap Direct3D. It hands you the device and the command queues, and you draw with them directly.

Two more programs ship beside the host. Both are optional.

ProgramWhat it doesShip it when
core.exeRuns the game.Always.
updater.exeChecks for a new version, then starts the game.You distribute the game yourself.
crashreporter.exeOffers to send a report after a crash.You run a crash report service.

Distributing a game covers both.

Before you start

You need:

  • Windows 10 or later, and a GPU with a Direct3D 12 driver
  • Visual Studio with the C++ desktop workload
  • Windows SDK 10.0.26100 or later
  • The Matchstick SDK

The SDK contains the runtime, the headers, and a sample game in src/samples/EmptyGame. The sample is the quickest way to begin: it builds a working module.dll with every callback stubbed out.

Lay out the game folder

The runtime zip in the SDK is already a complete install folder. Add a game folder to it and you have a game.

install folder
├── core.exe
├── updater.exe              optional
├── crashreporter.exe        optional
├── dependencies/            Visual C++ runtime installer
├── resources/
└── game/
    ├── game.json            name, version and settings
    ├── gameIcon.png         optional 48x48 window icon
    ├── bin/module.dll       your code
    └── content/             your data files

You own everything in green. Leave the rest of the runtime as it is.

The content folder is the root of the virtual file system. Your module can't read files outside it.

Describe the game

game.json tells the host what it is running. Three fields are required:

{% highlight json %} { "gameUid": "b7a1c2de-0f3a-4c57-9d1e-2f6a8e4b9c10", "gameName": "My Game", "version": "0.1" } {% endhighlight %}
FieldUsed for
gameUidKeeps this game's saves, preferences and logs apart from other games. Use a GUID.
gameNameThe window title.
versionUpdate checks and crash reports.

The same file sets default preferences and turns on updates, crash reports and statistics. See the game.json reference for every field.

To change the window title while the game runs, call SetWindowTitle.

Write the module

A module exports two functions. GetGraphicsRequirements tells the host which GPU features you need, and GetModule returns your game object.

{% highlight c++ %} #include #include #include "Module.hpp" extern "C" __declspec(dllexport) HRESULT GetGraphicsRequirements(MGDFGraphicsRequirements *requirements) { *requirements = {}; requirements->MinFeatureLevel = D3D_FEATURE_LEVEL_11_0; requirements->MinShaderModel = D3D_SHADER_MODEL_6_0; return S_OK; } extern "C" __declspec(dllexport) HRESULT GetModule(IMGDFModule **module) { auto m = MGDF::MakeCom(); m.AddRawRef(module); return S_OK; } {% endhighlight %}

The game object implements IMGDFModule. The host calls its methods, and each one receives the host interface for the thread it runs on.

{% highlight c++ %} class Module : public MGDF::ComBase { public: BOOL __stdcall STNew(IMGDFSimHost *host) final; BOOL __stdcall STUpdate(IMGDFSimHost *host, double elapsedTime) final; void __stdcall STShutDown(IMGDFSimHost *host) final; BOOL __stdcall RTBeforeFirstDraw(IMGDFRenderHost *host) final; BOOL __stdcall RTDraw(IMGDFRenderHost *host, double alpha) final; void __stdcall RTAfterPresent(IMGDFRenderHost *host) final; BOOL __stdcall RTBeforeBackBufferChange(IMGDFRenderHost *host) final; BOOL __stdcall RTBackBufferChange(IMGDFRenderHost *host) final; BOOL __stdcall RTBeforeDeviceReset(IMGDFRenderHost *host) final; BOOL __stdcall RTDeviceReset(IMGDFRenderHost *host) final; void __stdcall RTShutDown(IMGDFRenderHost *host) final; void __stdcall Panic() final; }; {% endhighlight %}

The prefix tells you the thread. ST methods run on the sim thread and RT methods run on the render thread.

CallbackCalledUse it to
STNewOnce, at startupSet up the game state.
STUpdateEvery tickRead input, play audio, advance the game.
STShutDownWhen the player quitsSave, then call host->ShutDown().
RTBeforeFirstDrawOnce, before the first frameCreate GPU resources.
RTDrawEvery frameRecord and submit your drawing.
RTAfterPresentEvery frame, after presentSubmit background GPU work.
RTBeforeBackBufferChange
RTBackBufferChange		Around a resizeRelease, then recreate, anything sized to the window.
RTBeforeDeviceReset
RTDeviceReset		Around a device lossRelease, then recreate, every GPU resource.
RTShutDownOnce, at exitRelease GPU resources.
PanicOn a fatal errorClean up without calling the host.

The game closes only when you say so. When the player quits, the host calls STShutDown and waits for you to call ShutDown:

{% highlight c++ %} void __stdcall Module::STShutDown(IMGDFSimHost *host) { host->ShutDown(); } {% endhighlight %}

NoteHost interfaces are COM objects. Hold them in MGDF::ComObject and they release themselves.

Share state between two threads

The sim thread and the render thread run at the same time. The sim thread owns the game state. The render thread only draws.

Keep the two apart. At the end of each tick, copy what the renderer needs into a snapshot and swap it in under a lock. RTDraw picks up the latest snapshot and draws from that alone.

{% highlight c++ %} BOOL __stdcall Module::STUpdate(IMGDFSimHost *host, double elapsedTime) { _world.Advance(elapsedTime); std::lock_guard lock(_mutex); _snapshot = _world.Snapshot(); return TRUE; } BOOL __stdcall Module::RTDraw(IMGDFRenderHost *host, double alpha) { Snapshot frame; { std::lock_guard lock(_mutex); frame = _snapshot; } return Draw(host, frame); } {% endhighlight %}

The sim thread ticks 60 times a second by default. Change the rate with the host.simFps preference.

Run the game

Build the module into game/bin and start core.exe. To debug, set core.exe as the debug command in Visual Studio.

The game folder doesn't have to live inside the runtime. Point the host at it instead:

core.exe -gamediroverride "C:\dev\mygame\game"

Every argument also works as an environment variable, and the host reads a .env file beside core.exe. That keeps your development settings off the command line:

MGDF_GAMEDIROVERRIDE="C:\dev\mygame\game"
MGDF_USERDIROVERRIDE=1
MGDF_LOGLEVEL=log_high
ArgumentWhat it does
-gamediroverrideRuns a game folder from another location.
-userdiroverrideKeeps saves, preferences and logs in a user folder beside the game.
-loglevelSets how much the host logs.

Without -userdiroverride, the host keeps user data in %LOCALAPPDATA%\MGDF\1\<gameUid>. That is where to look for the log when something goes wrong.

See the command line reference for the full list.
