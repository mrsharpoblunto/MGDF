Configuration Options

Command line options

Running core.exe from command line

The updater, a store client, or the developer starts core.exe. Each argument -name [value] also has an environment variable MGDF_NAME. For a flag, set the variable to a value such as 1. Command line arguments have priority over environment variables.

Before it reads the arguments, the core reads the file .env in the core.exe folder, if it is present. Each line is KEY=VALUE. Blank lines, comment lines that start with #, and quoted values are permitted. A value in .env does not replace an environment variable that is already set.

MGDF_LOGLEVEL=log_high
MGDF_GAMEDIROVERRIDE="C:\dev\mygame\game"
-vr
[Optional] Requests VR for this run without changing host.vr. The module must set MGDFGraphicsRequirements::VR to TRUE. See the VR guide.
-loglevel
[Optional] Sets the log level. The values, from the most detail to the least, are log_low, log_medium, log_high, and log_error.
-userdiroverride
[Optional] Stores user data (saved games, preferences, and logs) in a /user folder next to the game folder. Without -gamediroverride, the folder is user\<gameUid> in the core.exe folder. Without this flag, the folder is %LOCALAPPDATA%\MGDF\1\<gameUid>.
-gamediroverride
[Optional] Selects the game folder. The default is the /game folder in the core.exe folder.
-capturediroverride
[Optional] Selects the folder for screenshots and videos. The default is the captures folder in the user data folder. A relative path starts at the current folder.
-usedefaultadapter
[Optional] Skips Direct3D adapter enumeration, which can cause issues when running via the Visual Studio graphics debugger
-metricsport
[Optional] If specified, exposes a Prometheus metrics server on the given port that can record performance metrics
-logendpoint
[Optional] If specified, streams logs to a Loki server
-statisticsendpointoverride
[Optional] Replaces the statisticsService URL in game.json (see Statistics service).
-hideerrors
[Optional] Shows no error message and no crash dialog, and sends no crash report. When crash reports are on, the crash reporter keeps a minidump crash-<id>.dmp in the user data folder. Use this flag for automated tests.

Running updater.exe from command line

updater.exe reads game/game.json in its own folder and checks for an update (see Updating). It then starts core.exe with all of its own command line arguments, without change. For example, updater.exe -loglevel log_high starts core.exe -loglevel log_high. Do not run updater.exe as administrator. It then stops and does not start the game.

Game.json configuration

The game.json file contains the configuration and default preferences of a game. The core reads all the fields except updateService. Only the updater reads updateService. MGDF does not read other fields. The full schema is as follows:

{% highlight json %} { "gameUid":"a unique id", "gameName":"A human readable name", "version":"0.1", "crashReportService":"https://www.example.com/api/crashes", "privacyPolicy":"https://www.example.com/privacy", "statisticsService":"https://www.example.com/api/statistics", "updateService":"https://www.example.com/api/update.json", "preferences":{ "key":"value" } } {% endhighlight %}

Game.json schema

gameUid
[Required] A unique identifier that keeps the data of this game apart from other MGDF games. Use a GUID or a similar string that other games are not likely to use. The core uses it in the user data folder path, crash reports, and statistics.
gameName
[Required] The name of the game. It is the title of the game window (see IMGDFCommonHost SetWindowTitle), the update dialog, and the crash dialog.
version
[Required] The game version, with two to four numeric parts: major.minor[.build[.revision]]. Missing parts are zero. The core sends it with crash reports. The updater compares it with the version from the update service. The updater does not start the game if it cannot read this version.
crashReportService
[Optional] The URL of the crash report service (see Crash report service). Without this field, the crash reporter does not start.
privacyPolicy
[Optional] An HTTP or HTTPS URL. The crash dialog shows a link to it.
statisticsService
[Optional] The URL of the statistics service (see Statistics service). Without this field, the core sends no statistics.
updateService
[Optional] The HTTPS URL of the update service (see Update service). Only the updater reads this field.
preferences
[Optional] A dictionary of strings specifying any preferences used by the game. These can be accessed via the IMGDFGame Get/Set/HasPreference methods. A number of built in preferences are also used by the MGDF host and are always prefixed with host. The full list of built in preferences is shown below. These built in preferences can be overridden by specifying them in the game.json file.

Built in host preferences

host.vr
Requests VR at startup ("1") or window rendering ("0"). Defaults to "0". The module must opt in through MGDFGraphicsRequirements::VR. Use SetVR on IMGDFPendingRenderSettingsChange to change this setting. If a headset session cannot start, the game continues in the window and keeps the saved preference. See the VR guide.
host.musicVolume
A string value between 0 and 1 that sets the volume for all music played using IMGDFSoundStreams. Defaults to "1.0"
host.soundVolume
A string value between 0 and 1 that sets the volume for all sounds played using IMGDFSounds. defaults to "1.0"
host.simFps
The target framerate of the sim thread. If the sim thread is able to run faster than this, the host will add in sleeps between timesteps to ensure that the sim is limited to this framerate (note the render thread framerate is unaffected by this setting). Defaults to "60"
host.renderFps
The target framerate of the render thread. If vsync is disabled or the refresh rate of the monitor is faster, the host will add in sleeps between renders to ensure that the rendering is limited to this framerate (note the sim thread framerate is unaffected by this setting). Not set by default
host.screenX
The desired horizontal resolution to display the game at when running in fullscreen. If this resolution is not possible on the current display, then the native resolution will be used instead. Defaults to "1024"
host.screenY
The desired vertical resolution to display the game at when running in fullscreen. If this resolution is not possible on the current display, then the native resolution will be used instead. Defaults to "768"
host.fullScreen
Whether to start the game in fullscreen ("1") or in windowed mode ("0"). Defaults to "0"
host.fullScreenExclusive
Should fullscreen use exclusive mode ("1") or windowed mode ("0"). Defaults to "0"
host.vsync
Whether or not to use vsync on the render thread ("1"), or whether to render frames fast as possible ("0"). Defaults to "1"
host.lowLatencyMode
The low latency mode: "0" (off), "1" (on) or "2" (on with boost). The host uses "0" when GetLowLatencyMode on IMGDFRenderSettingsManager does not list the mode. Defaults to "1"
host.frameGeneration
The number of generated frames per rendered frame. "0" turns frame generation off. The host limits the value to GetMaxGeneratedFrames on IMGDFRenderSettingsManager. Defaults to "0"
host.rayTracing
Whether the module should use ray tracing ("1") or not ("0"). The host uses "0" when GetRayTracingSupport on IMGDFRenderSettingsManager returns FALSE. The host does nothing else with it; the module reads it with GetRayTracing. Defaults to "1"
host.windowResize
Whether to allow resizing of the game window in windowed mode ("1") or to have a fixed size window ("0"). This setting is provided as resizing the window may cause a D3D device reset. Because of this, having a resizable window means your game will have to be able to handle this. If you don't want to worry about this, leave it at the default of "0"
host.windowSizeX
The desired horizontal size of the window when in windowed mode. Defaults to "1024"
host.windowSizeY
The desired vertical size of the window when in windowed mode. Defaults to "768"
host.windowPositionX
The desired horizontal position of the window when in windowed mode. Defaults to null (position determined by the OS)
host.windowPositionY
The desired vertical position of the window when in windowed mode. Defaults to null (position determined by the OS)

Update service

The updater sends a GET request to the updateService URL in game.json. The service returns a JSON document that describes the newest version of the game. For the update flow, see Updating.

{% highlight json %} { "version": "1.2.3", "installerUrl": "https://www.example.com/NewGameSetup_1.2.3.exe", "sha256": "<64 hexadecimal digits>", "installerArguments": ["/S", "/D={installDir}"] } {% endhighlight %}

Update service schema

version
[Required] The newest version, with two to four numeric parts. Missing parts are zero. The updater offers the update only if this version is newer than the version in game.json.
installerUrl
[Required] The HTTPS URL of the installer.
sha256
[Required] The SHA-256 hash of the installer, as 64 hexadecimal digits. The updater does not run an installer with a different hash. The updater does not check installer signatures.
installerArguments
[Required] The installer command line arguments, one argument for each array entry. Use an empty array for no arguments. {installDir} changes to the install folder. The updater puts quotes around an argument that contains spaces or quotes. For NSIS, put /D={installDir} last. The updater does not put quotes around the /D= argument, also when the path has spaces.

Service rules

  • The updateService URL and installerUrl must use HTTPS. Redirects must also use HTTPS. For local tests, HTTP to a loopback IP address such as 127.0.0.1 is permitted.
  • The service must reply in 5 seconds. The response is limited to 64 KiB. A failed or late check starts the game with no message.
  • The installer has no size limit. The download stops if no data arrives for 60 seconds.
  • The updater does not send credentials. Make the installer URL available without a login.

Statistics service

The core sends the values that the game pushes with IMGDFStatisticsManager to the statisticsService URL in game.json. The core sends the values in batches: when 25 values are waiting, after 5 seconds, and when the game stops. Each batch is one POST request with a JSON body. The body uses gzip content encoding.

Request fields

gameUid
A string value.
sessionId
A string value. All the values from one session have the same session id.
statistics
An array of statistic objects containing the fields below.
  • timestamp A number. The time when the game pushed the value, in milliseconds from the start of the session.
  • name A string value.
  • value A string value.
  • tags An object with string values. It is empty when the value has no tags.

Sample HTTP request to https://example.com/statistics (the statisticsService URL in game.json is https://example.com/statistics). The body is shown before compression.

POST https://example.com/statistics HTTP/1.1
Content-Type: application/json
Content-Encoding: gzip
Host: example.com

{"gameUid":"blah","sessionId":"xxxx","statistics":[{"name":"key1","tags":{},"timestamp":0.0,"value":"value1"},{"name":"key2","tags":{"level":"2"},"timestamp":1500.0,"value":"value2"}]}

Response

Return HTTP status 200. The core does not read the response body. The core logs an error for any other status and does not send the batch again.

Crash report service

The crash reporter sends a report in two steps. First, it sends a POST request with the crash data to the crashReportService URL in game.json. The service returns an upload URL. Then the crash reporter sends a PUT request with the report zip file to that URL. A presigned S3 URL is one type of upload URL. For the report contents and the dialog, see Crash reports.

Request fields

detail
A string value. It starts with "The game stopped unexpectedly.", then gives the error text when there is one, and ends with the exit code of core.exe.
gameUid
A string value of the crashing game's uid.
gameVersion
A string value containing the version number of the game that crashed.
frameworkVersion
A string value containing the version number of the framework that the game was running on when it crashed.

Sample HTTP request to https://example.com/crashes (the crashReportService URL in game.json is https://example.com/crashes)

POST https://example.com/crashes HTTP/1.1
Content-Type: application/json
Host: example.com

{"detail":"The game stopped unexpectedly. Module: Unable to load level Exit code: 1.","gameUid":"blah","gameVersion":"1.2.3.4","frameworkVersion":"1.2.3.4"}

Response fields

success
A boolean value. Set it to true to accept the report.
uploadUrl
An absolute HTTP or HTTPS URL. The crash reporter sends the report zip file to this URL in a PUT request with Content-Type: application/zip.

Sample HTTP response

HTTP/1.1 200 OK
Content-Type: application/json; charset=UTF-8

{"success":true, "uploadUrl":"https://s3.amazonaws.com/yourbucket/crash.zip"}

Service rules

  • Both requests must return a 2xx status. The crash reporter does not follow redirects.
  • The POST response is limited to 64 KiB.
  • The upload stops if no data moves for 60 seconds. The player can also cancel it.
